# ユニットテストで書けないもの

`ImpressionSession` のテストは「**信号が来たとき**どう数えるか」を固定している。
固定できていないのは「**SwiftUI が本当にその信号を送るか**」で、これは実際に動かさないと分からない。

その境目にあるものを、危険な順に並べる。ここに挙げたものが `Example/` のサンプルアプリと
XCUITest の対象になる。**推測で「たぶん動く」と書かない** —— 分かっていないものは
「未検証」と書いて残す。

| # | 何が起きうるか | なぜユニットで書けないか | 危険度 | 実測 |
|---|---|---|---|---|
| H1 | **タブを離れても `onDisappear` が来ない**。SwiftUI の `TabView` は選択されていないタブの View を生かしておくことがある。来なければ露出の一区切りが終わらず、**戻ってきても二度と数えない** | タブの生存戦略は SwiftUI の実装依存 | 🔴 | ✅ 白（2026-08-09） |
| H2 | **シートを出し直すと数え直すか**。閉じて開き直したとき、View の同一性が変わるかどうかで結果が変わる | 同一性の扱いは SwiftUI の実装依存 | 🔴 | ✅ 白（2026-08-09） |
| H3 | **遅延生成の一覧で、画面外の行に `onScrollVisibilityChange(true)` が来ないか**。来ると「見えていないのに見えた」が静かに混ざる | `LazyVStack` の生成タイミングは実行時にしか決まらない | 🔴 | ✅ 白（2026-08-09） |
| H4 | **押し戻ってから入り直すと数え直すか**（`NavigationStack` の push → pop → push） | 同上 | 🟡 | ✅ 白（2026-08-09） |
| H5 | **1 秒たたずに離れたら数えないか**。実機の遷移アニメーションを挟んでも成り立つか | 実時間の絡む経路 | 🟡 | ✅ 白（2026-08-09） |
| H6 | **スクロールで通り過ぎたら数えないか / 戻ってきたら数え直すか** | スクロールの可視判定は実描画が要る | 🟡 | ✅ 白（2026-08-09） |
| H7 | **シートの中の View に `scenePhase` の変化が届くか**。届かないと背面で数え続ける | 環境値の伝播は実行時にしか分からない | 🟡 | 未検証 |
| H8 | **`onScrollVisibilityChange` のしきい値が「その要素自身の面積に対する割合」か**。器に対する割合だと、大きい要素が永久に数えられない | API の意味論。文書だけでは確かめきれない | 🟡 | 未検証 |
| H9 | **親の状態が変わって View が作り直されたとき、`onAppear` が再入して二重に数えないか** | 再作成は SwiftUI が決める | 🔴 | 部分的（H2/H4 で間接的に） |

## 検証の形

サンプルアプリは、危険ごとに 1 画面ずつ持つ。**画面には常に「いま何が何回出たか」を出しておき、
XCUITest はその文字列を読む**。スクリーンショットの目視では、回数のずれを見つけられない。

```
probe.readout   "screen_a=1 row=0 sheet=2"
```

滞在時間は起動引数で変えられる（`-dwell 2.0`）。**「1 秒たたずに離れる」を確かめるには、
テストの操作が 1 秒で終わる保証が要る**ので、そこだけ長くする。

## 実測して分かったこと（2026-08-09・iPhone シミュレータ / iOS 26）

**6 つとも白だった。** 実装の穴は見つかっていない。とくに大きいのは 2 つ。

- **H1 が白** —— `TabView` はタブを離れたときに `onDisappear` を送っていて、露出の一区切りが
  正しく終わる。戻ってくれば数え直す。**4 タブのアプリでも `trackScreen` がそのまま使える**
- **H3 が白** —— `onScrollVisibilityChange` は、遅延生成された画面外の行には `true` を送らない。
  `trackImpression` を `onAppear` に落とさなかった判断（`View+Track.swift` の注記）が、
  実測で裏付けられた

### 検証の途中で踏んだこと（実装ではなく、確かめ方の問題）

3 件落ちたが、**どれもハーネス側の書き方の問題**だった。取り違えると実装を壊しに行くので残す。

| 落ちたもの | 本当の原因 |
|---|---|
| 画面外の要素が数えられた | プローブを `LazyVStack` の**先頭**に置いていた。初期表示で画面内にあり、可視通知が来るのが正しい状態だった。**あやうく実装のバグと取り違えるところだった** |
| シートの中のボタンが見つからない | コンテナに `accessibilityIdentifier` を付けて子要素を集約していた |
| スクロールで対象に辿り着けない | `isHittable` がスクロールの中の要素について当てにならない。25 回送っても false のまま、実際には画面に出ていた。**要素が掴めたかではなく、数字が変わったかで進める** |

環境そのものでも 3 つ踏んだ: `TARGETED_DEVICE_FAMILY` を明示しないと iPad 専用扱いになる /
同名のシミュレータが複数ランタイムにあると名前指定が解決に失敗する（id で指す）/
テストバンドルの Info.plist は自動生成に倒す。
